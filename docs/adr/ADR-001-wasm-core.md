# ADR-001: Run the real Rust core in the browser demo via WebAssembly

- **Status:** Accepted (go), Nov 4, 2026
- **Task:** P00-T03 (spike b)
- **Evidence:** [docs/evidence/P00-T03-spikes.md](../evidence/P00-T03-spikes.md)

## Context
The judge demo must run the real DORMBIT workflow on synthetic data with no install. The plan's preferred design compiles `dormbit-core` to `wasm32-unknown-unknown` so the browser uses the same capsule writer, verifier, and restore planner as the native app. The fallback was a TypeScript port held to the same golden fixtures, which doubles the code and splits the source of truth.

The risk was that the core's dependencies would not compile for wasm32, or would produce different bytes there, which would break golden tests (PROP-10).

## Spike result
All of the core's planned dependencies compiled for `wasm32-unknown-unknown` with Rust 1.99.1:
`sha2 0.11.1`, `tar 0.4.46`, `flate2 1.1.10` (pure-Rust `miniz_oxide` backend), `ignore 0.4.34` (gitignore matcher only), `unicode-normalization 0.1.26`, `uuid 1.29.0` (no RNG features), `wasm-bindgen 0.2.130`.

A deterministic capsule-shaped tar (marker, manifest, per-file gzipped objects, trailer) produced **identical bytes** natively and in WebAssembly run under Node 24:
- native `tar_sha256=45ea70cc…854e205e`, length 7168
- wasm `tar_sha256=45ea70cc…854e205e`, length 7168
- WebCrypto re-hash of the wasm tar bytes matched the Rust digest (`WEBCRYPTO_MATCHES_RUST=true`)

Gitignore matching (including a negated rule), NFC normalization, and uuid formatting also matched.

Size: 1.24 MB raw release build, 780 KB after `wasm-opt -Oz`, 330 KB gzipped. Acceptable for a static demo page.

## Decision
Go. `dormbit-core` targets both native and wasm32. To keep it portable:
- Core does no I/O directly; it uses a `Vfs` trait plus injected `Clock` and `IdGen`.
- IDs are generated by the host (native RNG or `crypto.randomUUID()` in the browser), so core needs no `getrandom` backend.
- `flate2` uses the `rust_backend` feature only; no C zlib.
- `wasm-bindgen` is pinned exactly (`=0.2.130`) to match the installed `wasm-bindgen-cli`.

## Consequences
- PROP-10 (byte-identical capsules across builds) is testable and becomes a CI check.
- The TypeScript-port fallback is dropped unless a later dependency breaks wasm32.
- Any new core dependency must be checked with `cargo build --target wasm32-unknown-unknown` before merging.
